**Arquivo 1: Introdução e Cadeias de Filtro**
Filtros de firewall são utilizados para permitir ou bloquear pacotes específicos encaminhados para sua rede local, originados do seu roteador ou destinados ao roteador. Existem dois métodos para configurar a filtragem: Permitir tráfego específico e descartar todo o resto; Descartar apenas tráfego malicioso e permitir todo o resto. Ambos os métodos possuem prós e contras. Por exemplo, do ponto de vista da segurança, o primeiro método é muito mais seguro, mas exige intervenção do administrador sempre que o tráfego para um novo serviço precisar ser aceito. Esta estratégia oferece um bom controle sobre o tráfego e reduz a possibilidade de uma brecha devido à má configuração de um serviço. Por outro lado, ao proteger a rede de um cliente, seria um pesadelo administrativo aceitar todos os serviços possíveis que os usuários possam utilizar. Portanto, um planejamento cuidadoso do firewall é essencial em configurações avançadas. Um filtro de firewall consiste em três cadeias (chains) predefinidas que não podem ser excluídas: input - usada para processar pacotes que entram no roteador através de uma das interfaces com o endereço IP de destino sendo um dos endereços do próprio roteador. Pacotes que apenas passam pelo roteador não são processados pelas regras da cadeia input. forward - usada para processar pacotes que passam pelo roteador. output - usada para processar pacotes que se originam no roteador e saem por uma de suas interfaces. Pacotes que apenas passam pelo roteador não são processados pelas regras da cadeia output. A configuração do filtro de firewall é acessível pelo menu ip/firewall/filter para IPv4 e ipv6/firewall/filter para IPv6.

**Arquivo 2: IPv4 - Proteção do Roteador**
Exemplo de Firewall. Vejamos um exemplo básico de firewall para proteger o próprio roteador e os clientes atrás dele, tanto para os protocolos IPv4 quanto IPv6. Firewall IPv4. Proteger o próprio roteador. Regras de ouro seguidas para configurar o firewall: Trabalhar com conexões novas para diminuir a carga no roteador; Aceitar o que você precisa; Descartar (drop) todo o resto; log=yes pode ser definido para registrar alguns atacantes, mas lembre-se que isso pode aumentar a carga na CPU durante ataques pesados. Sempre começamos aceitando conexões já conhecidas e aceitas, portanto, a primeira regra deve ser aceitar conexões "established" (estabelecidas) e "related" (relacionadas). /ip firewall filter add action=accept chain=input comment="default configuration" connection-state=established,related. Agora podemos prosseguir aceitando algumas novas conexões. Em nosso exemplo, queremos permitir o acesso ao protocolo ICMP de qualquer endereço e todo o resto apenas da faixa de endereços 192.168.88.2-192.168.88.254. Para isso, criamos uma lista de endereços (address-list) e duas regras de firewall. /ip firewall address-list add address=192.168.88.2-192.168.88.254 list=allowed_to_router. /ip firewall filter add action=accept chain=input src-address-list=allowed_to_router. add action=accept chain=input protocol=icmp. E, por último, descartamos todo o resto: add action=drop chain=input.

**Arquivo 3: IPv4 - Proteção da LAN (Listas de Endereços)**

**Arquivo 4: IPv4 - Proteção da LAN (Regras de Filtro)**
Breve explicação das regras de filtro: Pacotes com connection-state=established,related adicionados ao FastTrack para maior taxa de transferência; o firewall trabalhará apenas com novas conexões; Descartar conexões inválidas e registrá-las com o prefixo "invalid"; Descartar tentativas de alcançar endereços não públicos a partir da sua rede local; aplica a address-list=not_in_internet anteriormente; "bridge" é a interface da rede local; log=yes para tentativas com o prefixo "!public_from_LAN"; Descartar pacotes de entrada que não passaram por NAT; ether1 é a interface pública; registrar tentativas com prefixo "!NAT"; Pular (jump) para a cadeia ICMP para descartar mensagens ICMP indesejadas; Descartar pacotes vindos da Internet que não são endereços IP públicos; ether1 é a interface pública; registrar tentativas com o prefixo "!public"; Descartar pacotes da LAN que não possuem IP da LAN; 192.168.88.0/24 é a sub-rede usada na rede local. /ip firewall filter add action=fasttrack-connection chain=forward comment=FastTrack connection-state=established,related add action=accept chain=forward comment="Established, Related" connection-state=established,related add action=drop chain=forward comment="Drop invalid" connection-state=invalid log=yes log-prefix=invalid add action=drop chain=forward comment="Drop tries to reach not public addresses from LAN" dst-address-list=not_in_internet in-interface=bridge log=yes log-prefix=!public_from_LAN out-interface=!bridge add action=drop chain=forward comment="Drop incoming packets that are not NAT`ted" connection-nat-state=!dstnat connection-state=new in-interface=ether1 log=yes log-prefix=!NAT add action=jump chain=forward protocol=icmp jump-target=icmp comment="jump to ICMP filters" add action=drop chain=forward comment="Drop incoming from internet which is not public IP" in-interface=ether1 log=yes log-prefix=!public src-address-list=not_in_internet add action=drop chain=forward comment="Drop packets from LAN that do not have LAN IP" in-interface=bridge log=yes log-prefix=LAN_!LAN src-address=!192.168.88.0/24.

**Arquivo 6: IPv6 - Proteção do Roteador**
Firewall IPv6. Proteger o próprio roteador. Muito semelhante à configuração IPv4, exceto que temos que lidar com mais protocolos necessários para o funcionamento correto do IPv6. Primeiro, criamos uma address-list a partir da qual você permite o acesso ao dispositivo: /ipv6 firewall address-list add address=fd12:672e:6f65:8899::/64 list=allowed. Breve explicação das regras de filtro IPv6: Trabalhar com novos pacotes, aceitar pacotes established/related; Descartar endereços link-local vindos da interface/lista de interfaces da Internet (pública); Aceitar acesso ao roteador a partir de endereços link-local, aceitar endereços multicast para fins de gerenciamento, aceitar sua lista de endereços de origem para acesso ao roteador; Descartar qualquer outra coisa; /ipv6 firewall filter add action=accept chain=input comment="allow established and related" connection-state=established,related add chain=input action=accept protocol=icmpv6 comment="accept ICMPv6" add chain=input action=accept protocol=udp port=33434-33534 comment="defconf: accept UDP traceroute" add chain=input action=accept protocol=udp dst-port=546 src-address=fe80::/10 comment="accept DHCPv6-Client prefix delegation." add action=drop chain=input in-interface=in_interface_name log=yes log-prefix=dropLL_from_public src-address=fe80::/10 add action=accept chain=input comment="allow allowed addresses" src-address-list=allowed add action=drop chain=input. /ipv6 firewall address-list add address=fe80::/16 list=allowed add address=xxxx::/48 list=allowed add address=ff02::/16 comment=multicast list=allowed. Em certas configurações onde o relay DHCPv6 é usado, o endereço de origem dos pacotes pode não ser da faixa link-local. Nesse caso, o parâmetro src-address da regra #4 deve ser removido ou ajustado para aceitar o endereço do relay.

**Arquivo 7: IPv6 - Proteção da LAN**
Proteger os dispositivos da LAN. Esta etapa é mais importante do que no IPv4. Nas configurações IPv4, os clientes geralmente têm endereços de uma faixa local e passam por NAT para um IP público; dessa forma, não são diretamente acessíveis a partir de redes públicas. O IPv6 é uma história diferente. Na maioria das configurações comuns, o IPv6 habilitado torna seus clientes disponíveis a partir de redes públicas, portanto, regras de filtro de firewall adequadas para proteger seus clientes são obrigatórias. Em resumo, uma proteção básica de LAN deve: Aceitar established/related e trabalhar com novos pacotes; Descartar pacotes inválidos; Aceitar pacotes ICMPv6; Aceitar novas conexões originadas apenas de seus clientes para a rede pública; Descartar todo o resto. /ipv6 firewall filter add action=accept chain=forward comment=established,related connection-state=established,related add action=drop chain=forward comment=invalid connection-state=invalid log=yes log-prefix=ipv6,invalid add action=accept chain=forward comment=icmpv6 in-interface=!in_interface_name protocol=icmpv6 add action=accept chain=forward comment="local network" in-interface=!in_interface_name src-address-list=allowed add action=drop chain=forward log-prefix=IPV6.

**Arquivo 8: Correspondências e Ações de Filtro**
Matchers (Correspondências). Todas as propriedades de correspondência (matcher) são comuns e estão listadas na documentação. Actions (Ações). As tabelas abaixo mostram a lista de ações específicas de filtro e propriedades associadas. Propriedade: action (nome da ação; Padrão: accept). Descrição: accept - aceita o pacote. O pacote não é passado para a próxima regra. add-dst-to-address-list - adiciona o endereço de destino à lista especificada. add-src-to-address-list - adiciona o endereço de origem à lista especificada. drop - descarta silenciosamente o pacote. fasttrack-connection - processa pacotes usando FastPath (apenas IPv4). jump - pula para uma cadeia definida pelo usuário. log - adiciona mensagem ao log do sistema (interface, MAC, IP, porta, etc.). passthrough - incrementa contador e vai para a próxima regra (útil para estatísticas). reject - descarta e envia mensagem ICMP de rejeição. return - devolve o controle para a cadeia de onde ocorreu o jump. tarpit - captura e segura conexões TCP (responde com SYN/ACK ao SYN). Apenas IPv4. hw-offload (no | yes; Padrão: yes): Habilita ou desabilita o descarregamento de hardware do FastTrack. reject-with (opções variadas; Padrão: icmp-no-route): Especifica o erro ICMP a ser enviado se o pacote for rejeitado (admin-prohibited, port-unreachable, tcp-reset, etc.).

**Arquivo 9: Detalhes da Ação Rejeitar (Reject-with)**
Detalhes do reject-with: icmp-no-route: envia mensagem ICMP address no-route. Tipo 1, código 0. icmp-admin-prohibited: envia mensagem ICMP address prohibited. Tipo 1, código 1. icmp-not-neighbour: envia mensagem ICMP address not-member. Tipo 1, código 2. icmp-address-unreachable: envia mensagem ICMP address unreachable. Tipo 1, código 3. icmp-port-unreachable: envia mensagem ICMP port unreachable. Tipo 1, código 4. tcp-reset: envia reset de conexão TCP. Tipo 1, código 6. icmp-err-src-routing-header: envia mensagem de erro no cabeçalho de rota. Tipo 1, código 7. icmp-headers-too-long: envia mensagem de cabeçalhos muito longos. Tipo 1, código 8.

**Arquivo 10: Filtragem RAW e Exemplo OSPF**
Filtragem RAW. A tabela RAW do firewall permite ignorar ou descartar pacotes seletivamente antes do rastreamento de conexão (connection tracking), reduzindo significativamente a carga na CPU. É muito útil para mitigação de ataques DoS/DDoS. A configuração RAW é acessível em ip/firewall/raw para IPv4 e ipv6/firewall/raw para IPv6. A tabela RAW não possui correspondentes (matchers) que dependam do rastreamento de conexão (como connection-state, layer7, etc.). Se um pacote é marcado para ignorar o rastreamento, a desfragmentação do pacote não ocorrerá. Além disso, o firewall RAW possui regras apenas em duas cadeias: prerouting - usada para processar qualquer pacote que entra no roteador. output - usada para processar pacotes originados no roteador. Ação específica RAW: action (nome da ação; Padrão: accept). Descrição: notrack - não envia o pacote para o connection tracking. Útil quando você ainda precisa do firewall regular, mas não exige rastreamento de conexão. Exemplo Básico RAW: Suponha que tenhamos uma configuração OSPF, mas devido ao rastreamento de conexão, o OSPF tenha problemas de adjacência. Podemos usar regras RAW para corrigir isso, não enviando pacotes OSPF para o rastreamento de conexão. /ip firewall raw add chain=prerouting protocol=ospf action=notrack add chain=output protocol=ospf action=notrack.
